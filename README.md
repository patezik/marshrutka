# Передайте за проезд

Браузерный симулятор водителя маршрутки. Ведёшь маршрутку по вечернему городу, подбираешь людей на остановках, считаешь сдачу в уме и стараешься не уронить стоящих пассажиров резким торможением.

**Чему учит игра (механикой, а не текстом):**
- **Устный счёт и деньги.** Сдачу нужно собрать монетами и купюрами из лотка, на ходу, пока ждёт очередь. Сумму на тарелке игра не показывает (до покупки «калькулятора»).
- **Инерция.** Резкий тормоз или газ — стоящие падают, пассажиры наклоняются, машина клюёт носом, мелочь слетает с тарелки.
- **Экономика смены.** Чек в конце: выручка − бензин − аренда − штрафы. Видно, во что обходятся спешка и ошибки.
- **Внимательность.** С 3-го дня встречаются хитрецы, которые дают меньше, чем нужно (бегают глазами). Им — ✗.

## Управление

| Действие | Мышь / тач | Клавиатура |
|---|---|---|
| Газ / тормоз | педали справа внизу | → / ← (или W/S, A/D, пробел) |
| Положить монету на тарелку | клик по лотку | 1–8 |
| Убрать с тарелки | клик по монете / ↺ | Backspace |
| Отдать сдачу | ✓ | Enter |
| «Не хватает» / «а помельче нет?» | ✗ | X |
| Пауза | ❚❚ | Esc |

Чтобы открылись двери, остановись так, чтобы дверь была напротив знака: пунктир станет зелёным. Пассажиры, которым скоро выходить, показывают значок своей остановки. Он же пульсирует на полосе маршрута сверху.

## Стек

- **Клиент:** Vite + TypeScript, Canvas 2D. Вся графика и звук генерируются кодом: ни одной картинки, звук через WebAudio.
- **Сервер:** Node.js + Express (`server/index.js`).
- **БД:** везде PostgreSQL.
  - **На хостинге:** облачная база (Neon), строка подключения задаётся в `DATABASE_URL`.
  - **Локально:** если `DATABASE_URL` не задан, `npm run dev` сам скачивает и запускает отдельный сервер PostgreSQL (пакет `embedded-postgres`). Файлы лежат в `.data/pg`, сервер работает на `localhost:5433`. Это dev-зависимость, на хостинге она не используется.

Таблицы (`server/db.js`):
- `players` — водители (анонимный id хранится в localStorage);
- `saves` — деньги, день, машины, тюнинг;
- `shifts` — история каждой смены: выручка, штрафы, точность сдачи, среднее время. По ней строятся график «как я считаю» и доска почёта.

Прибыль считает сервер, покупки он проверяет по общему каталогу `shared/catalog.js`.

## Запуск локально

```bash
npm install
```

```bash
npm run dev
```

Откроется http://localhost:5173. API работает на :3001, Vite проксирует к нему `/api`.

### Как зайти в базу

**1. Встроенный просмотрщик (только чтение).** При запущенном `npm run dev` откройте http://localhost:5173/db.html. Таблицы обновляются раз в 3 секунды, а для SQL-запросов есть готовые примеры. Записать что-то через просмотрщик нельзя, поэтому случайно ничего не удалите. В проде этой страницы нет.

**2. DBeaver / pgAdmin / psql (чтение и изменение).** Пока запущен `npm run dev`, подключитесь к локальному серверу:

| Параметр | Значение |
|---|---|
| Host | `localhost` |
| Port | `5433` |
| Database | `marshrutka` |
| User | `depot` |
| Password | `depot` |

В DBeaver: **База данных → Новое соединение → PostgreSQL** → введите параметры из таблицы → **Готово**. Таблицы будут в `marshrutka → Схемы → public → Таблицы`. Ячейки редактируются двойным кликом, потом нужно нажать **Сохранить** (Ctrl+S). SQL-запросы любые (`UPDATE`, `DELETE`, `ALTER TABLE`…) пишутся через **SQL-редактор** (Ctrl+]).

Например, выдать себе денег:

```sql
UPDATE saves SET money = money + 10000;
```

Изменения увидите в игре после перезагрузки страницы.

**3. База на хостинге (Neon).** В панели Neon есть разделы **Tables** (просмотр и правка таблиц) и **SQL Editor**. Подключить DBeaver можно и к облачной базе: параметры берутся из строки `DATABASE_URL`, SSL должен быть включён.

**Структура таблиц** описана в `SCHEMA` в `server/db.js`, таблицы создаются при старте сервера. Команда `CREATE TABLE IF NOT EXISTS` не меняет уже существующие таблицы, поэтому чтобы добавить колонку, нужен ещё `ALTER TABLE ...` (выполнить в DBeaver/Neon или дописать в код).

Прод-режим локально:

```bash
npm run build
```

```bash
npm start
```

## Публикация: GitHub Pages + Supabase (бесплатно)

GitHub Pages умеет отдавать только статические файлы, поэтому на сайте нет сервера на Express. Браузер обращается к базе Supabase (PostgreSQL) напрямую, через функции из `supabase/schema.sql`:
- `create_player` — создать водителя;
- `get_player` — загрузить водителя;
- `rename_player` — сменить имя;
- `submit_shift` — записать смену; аренду и прибыль считает сама база;
- `buy` — купить машину или тюнинг, деньги проверяет база;
- `player_history` — последние смены для графика;
- `leaderboard` — доска почёта.

Таблицы снаружи закрыты (Row Level Security), а функции проверяют данные так же, как раньше это делал сервер.

**Настройка (один раз):**
1. На [supabase.com](https://supabase.com) создайте проект.
2. В **SQL Editor** вставьте весь файл `supabase/schema.sql` и нажмите **Run**.
3. В **Project Settings → API Keys** (или кнопка **Connect**) скопируйте **Project URL** и **Publishable key** (`sb_publishable_…`). Это публичные данные, их можно встраивать в сайт.
4. В репозитории на GitHub откройте **Settings → Secrets and variables → Actions → Variables** и добавьте переменные `SUPABASE_URL` и `SUPABASE_KEY`.
5. **Actions → Deploy to GitHub Pages → Run workflow.** Дальше сайт пересобирается сам при каждом push в `main`.

Сайт: `https://<логин>.github.io/marshrutka/`.

На бесплатном тарифе Supabase ставит проект на паузу, если в него не заходили неделю. Включается он кнопкой **Restore** в панели Supabase, данные при этом сохраняются.

Локальная разработка (`npm run dev`) по-прежнему работает со своим сервером и локальным PostgreSQL. Если создать файл `.env.local` с `VITE_SUPABASE_URL` и `VITE_SUPABASE_KEY`, игра и локально будет ходить в Supabase.
